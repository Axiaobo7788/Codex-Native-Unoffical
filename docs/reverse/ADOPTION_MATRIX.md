> **Baseline Audited**: `Codex-Native-Unoffical` `HEAD` (`17f08f3`) vs ChatGPT Desktop (`26.326.51703` / `codex-cli 0.167.0-alpha.3.2`)
> **Governing ADR**: `ADR-032` (superseding and recalibrating `ADR-031`)

---

## 1. Adoption Classification Taxonomy

Every design decision in this matrix uses one of six explicit adoption categories:

1. **`ADOPT_PATTERN`** — Adopt the structural pattern or state model, implemented idiomatic to Flutter/Dart/Rust.
2. **`ADAPT_NATIVE`** — Adapt the concept to native Flutter Sliver / Rust `codex-native-host` characteristics rather than copying Electron/React magic numbers.
3. **`COPY_MEASURED_BEHAVIOR`** — Match measured visual tokens, layout proportions, keyboard shortcuts, and interaction polish.
4. **`KEEP_OUR_ADVANTAGE`** — Preserve areas where `Codex-Native-Unoffical` (`HEAD`) is already cleaner, safer, or higher-performance than Electron.
5. **`DO_NOT_ADOPT`** — Reject Electron/Node runtime coupling, system-prompt copying (`AGENTS.md` Rule #1), direct SQLite mutation of `~/.codex/*`, or private `/backend-api/*` / `/wham/*` dependencies in core.
6. **`RESEARCH_MORE`** — Defer commitment where behavior depends on undocumented cloud gates or uninspected mobile clients.

## 3. Concrete Code-Review & Architectural Debt Items in Current `HEAD` (`17f08f3`)

When the repository next enters a **Desktop Polish / Architecture Refinement** implementation phase, these five concrete, code-verified items from our `HEAD` audit should be prioritized before any new feature expansion:

1. **[Debt 16.A — Cross-Thread Scroll Anchor Restoration]** ([`lib/src/app/presentation/conversation.dart:91`](file:///home/axiaobo/%E6%96%87%E6%A1%A3/flutter%20projects/Codex-Native-Unoffical/lib/src/app/presentation/conversation.dart#L91), [`lib/src/features/conversation/history_controller.dart:80-124`](file:///home/axiaobo/%E6%96%87%E6%A1%A3/flutter%20projects/Codex-Native-Unoffical/lib/src/features/conversation/history_controller.dart#L80-L124)):
   - **Problem**: `_threadScrollOffsets` stores `threadId -> raw pixel offset (double)`, while `HistoryController.bindThread(threadId)` clears `_turns` and fetches only the newest page (`turnPageSize = 20`). If a user loads 3 pages of older turns (`60` turns), scrolls to `-4000 px`, switches to another thread, and switches back, only `20` turns are loaded and clamping `-4000 px` lands on the wrong turn.
   - **Fix (`ADAPT_NATIVE`)**: Store a structured scroll anchor `(anchorTurnId, anchorItemId, relativeOffset)` per thread and pair it with a small bounded multi-thread history LRU (e.g., `3..5` inactive threads in `HistoryController`, pinning any thread with an active turn or pending approval).
2. **[Debt 16.B — `maxRetainedTurns = 100` Eviction Edge in `HistoryController.loadOlderTurns()`]** ([`lib/src/features/conversation/history_controller.dart:175-179`](file:///home/axiaobo/%E6%96%87%E6%A1%A3/flutter%20projects/Codex-Native-Unoffical/lib/src/features/conversation/history_controller.dart#L175-L179)):
   - **Problem**: `_turns` is stored in descending order (`index 0` = newest turn). When `loadOlderTurns()` appends older turns and `_turns.length > maxRetainedTurns (100)`, `_turns.removeRange(0, _turns.length - maxRetainedTurns)` removes the **newest** turns (`index 0..k`). Because `_ConversationScrollView` (`anchor: 1.0`) places `reverseIndex 0` (the newest turn) at `center`, removing newest turns shifts the scroll layout extent of every older turn above `center` while the user is actively reading older history. Furthermore, existing tests in `test/features/conversation/history_controller_test.dart` only test `30 -> 40` turns (below the `100` cap).
   - **Fix (`ADAPT_NATIVE`)**: Preserve viewport anchor stability when `_windowShifted` triggers at `>100` turns (by compensating scroll offset or anchoring the sliver center to the active viewport turn) and add unit + widget tests exercising `>100` turns (`100 -> 120` turns).
3. **[Debt 16.C — Domain Layer Circular Import]** ([`lib/src/domain/history_models.dart:3`](file:///home/axiaobo/%E6%96%87%E6%A1%A3/flutter%20projects/Codex-Native-Unoffical/lib/src/domain/history_models.dart#L3) <-> [`lib/src/domain/thread_models.dart:3`](file:///home/axiaobo/%E6%96%87%E6%A1%A3/flutter%20projects/Codex-Native-Unoffical/lib/src/domain/thread_models.dart#L3)):
   - **Problem**: `history_models.dart` imports `thread_models.dart` (for `SortDirection`), while `thread_models.dart` imports `history_models.dart` (for `parseUserMessagePresentation` in `ThreadSummary.displayTitle`).
   - **Fix (`KEEP_OUR_ADVANTAGE`)**: Extract `SortDirection` or `user_message_presentation.dart` into a leaf file under `lib/src/domain/` so domain models form a strict DAG.
4. **[Debt 16.D — `_RenderConversationViewport` Custom RenderObject Audit]** ([`lib/src/app/presentation/conversation.dart:747-796`](file:///home/axiaobo/%E6%96%87%E6%A1%A3/flutter%20projects/Codex-Native-Unoffical/lib/src/app/presentation/conversation.dart#L747-L796)):
   - **Problem**: `_RenderConversationViewport` shifts `child.parentData.paintOffset` upward in `performLayout()` when `totalExtent < size.height` so short conversations top-align inside an `anchor: 1.0` viewport.
   - **Fix (`ADAPT_NATIVE`)**: Add targeted widget hit-testing and accessibility semantics tests for short vs overflowed viewports to verify that `paintOffset` adjustment never desynchronizes pointer hit testing or selection geometry.
5. **[Debt 16.E — User Envelope Heuristic Precedence & Deduplication]** ([`lib/src/domain/history_models.dart:69-194`](file:///home/axiaobo/%E6%96%87%E6%A1%A3/flutter%20projects/Codex-Native-Unoffical/lib/src/domain/history_models.dart#L69-L194)):
   - **Problem**: `parseUserMessagePresentation` uses string prefix matching (`# Files pasted by the user:`, `## My request for Codex:`) and regexes alongside `HistoryProtocolAdapter._userAttachments`.
   - **Fix (`ADAPT_NATIVE`)**: Ensure structured `UserInput` attachments (`localImage`, `image`, `skill`, `mention`) take strict precedence with deterministic deduplication and bounded input scanning.
