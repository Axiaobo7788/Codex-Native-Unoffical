# Calibrated Architecture Adoption Matrix & Evidence Reconciliation

> **Baseline Audited**: `Codex-Native-Unoffical` `HEAD` (`17f08f3`) vs ChatGPT Desktop (`26.326.51703` / `codex-cli 0.167.0-alpha.3.2`)
> **Governing ADR**: `ADR-032` (superseding and recalibrating `ADR-031`)

---

## 1. Adoption Classification Taxonomy

Every design decision in this matrix uses one of six explicit adoption categories:

1. **`ADOPT_PATTERN`** — Adopt the structural pattern or state model, implemented idiomatic to Flutter/Dart/Rust.
2. **`ADAPT_NATIVE`** — Adapt the concept to native Flutter Sliver / Rust `codex-native-host` characteristics rather than copying Electron/React magic numbers.
3. **`COPY_MEASURED_BEHAVIOR`** — Match measured visual tokens, layout proportions, keyboard shortcuts, and interaction polish.
4. **`KEEP_OUR_ADVANTAGE`** — Preserve areas where `Codex-Native-Unoffical` (`HEAD`) is already cleaner, safer, or higher-performance than Electron.
5. **`DO_NOT_ADOPT`** — Reject Electron/Node runtime coupling, system-prompt copying (`AGENTS.md` Rule #1), direct SQLite mutation of `~/.codex/*`, or private `/backend-api/*` / `/wham/*` dependencies in core.
6. **`RESEARCH_MORE`** — Defer commitment where behavior depends on undocumented cloud gates or uninspected mobile clients.

## 3. Concrete Code-Review & Architectural Debt Items (`16.A–16.E` — Implemented, Recalibrated & Verified)

All five concrete items identified in the `17f08f3` / `99e6141` `HEAD` audit have been implemented, hardened across boundary edge cases, unit/widget regression-tested, and live-walkthrough verified:

1. **[Debt 16.A — Cross-Thread Scroll Anchor Restoration (RESOLVED)]** ([`lib/src/app/presentation/conversation.dart`](lib/src/app/presentation/conversation.dart), [`test/app/bounded_timeline_test.dart`](test/app/bounded_timeline_test.dart)):
   - **Problem**: `_threadScrollOffsets` stored `threadId -> raw pixel offset (double)`, while `HistoryController.bindThread(threadId)` cleared `_turns` and fetched only the newest page (`turnPageSize = 20`). Switching away from a thread where `>1` page of older turns was loaded and switching back clamped `-4000 px` onto the wrong turn.
   - **Implemented Fix (`ADAPT_NATIVE`)**: Replaced raw pixel offsets with `_ThreadScrollBookmark(scrollPixels, anchorItemKey, anchorTurnId, anchorViewportTopDy)` (`_maxRetainedThreadScrollBookmarks = 32` LRU, pruning deleted threads and clearing on `Jump to latest` or within `_followThresholdPixels = 160.0`). On thread return, `_scheduleThreadScrollRestore` pages older turns on demand bounded to `_maxRestorePages = 10` older-page requests (covering roughly the initial page plus up to `10 × 20` additional turns, subject to deduplication and `maxRetainedTurns = 100` sliding-window eviction) until `anchorTurnId` is present, then aligns `anchorItemKey` to its `anchorViewportTopDy`. When an anchor remains absent after `_maxRestorePages` or when no older turns remain, **Scheme A** discards the stale bookmark and resets deterministically to the newest boundary (`pixels == 0.0`) rather than clamping raw `scrollPixels` onto the wrong turn window.
2. **[Debt 16.B — `maxRetainedTurns = 100` Eviction Edge in `HistoryController.loadOlderTurns()` (RESOLVED)]** ([`lib/src/features/conversation/history_controller.dart`](lib/src/features/conversation/history_controller.dart), [`lib/src/app/presentation/conversation.dart`](lib/src/app/presentation/conversation.dart)):
   - **Problem**: When `loadOlderTurns()` appended older turns past `maxRetainedTurns = 100`, `_turns.removeRange(0, evictedTurnCount)` removed the newest turns at `reverseIndex 0..k-1`, shifting the reverse index of every older turn and causing `SliverMultiBoxAdaptorElement` to rebind mounted children to different items and jump the viewport.
   - **Implemented Fix (`ADAPT_NATIVE`)**: Wired `findChildIndexCallback` into `_ConversationScrollView`'s `SliverList.builder` (`ValueKey('measured-$itemKey')`), widened `_averageMeasuredItemHeight` clamp to `(24.0, 4096.0)`, and used `HistoryController.loadOlderVersion` + `_MeasuredTimelineItem` + `_schedulePostLoadAnchorAlignment` to align the pre-load visible anchor after rebuild (`0.0 px` drift across `285,523 px` 100-turn real thread in Stage 3). `HistoryController.evictionVersion` and `lastEvictedItemIds` track sliding-window eviction state and prune evicted `history-<id>` entries from `_measuredItemHeights`.
3. **[Debt 16.C — Domain Layer Circular Import (RESOLVED)]** ([`lib/src/domain/user_message_presentation.dart`](lib/src/domain/user_message_presentation.dart), [`lib/src/domain/history_models.dart`](lib/src/domain/history_models.dart), [`lib/src/domain/thread_models.dart`](lib/src/domain/thread_models.dart)):
   - **Problem**: `history_models.dart` imported `thread_models.dart` while `thread_models.dart` imported `history_models.dart`.
   - **Implemented Fix (`KEEP_OUR_ADVANTAGE`)**: Extracted `UserAttachmentKind`, `UserAttachment`, `UserMessagePresentation`, `normalizeUserAttachment`, `normalizeUserAttachments`, and `parseUserMessagePresentation` into leaf module `lib/src/domain/user_message_presentation.dart` with zero `domain/` imports, eliminating all circular dependencies in `lib/src/domain/`.
4. **[Debt 16.D — `_RenderConversationViewport` Custom RenderObject Audit (RESOLVED)]** ([`lib/src/app/presentation/conversation.dart`](lib/src/app/presentation/conversation.dart), [`test/app/bounded_timeline_test.dart`](test/app/bounded_timeline_test.dart)):
   - **Problem**: `_RenderConversationViewport` shifts `child.parentData.paintOffset` (`SliverPhysicalParentData`) upward in `performLayout()` when `totalExtent < size.height` so short conversations top-align inside an `anchor: 1.0` viewport.
   - **Implemented Fix (`ADAPT_NATIVE`)**: Audited Flutter's `RenderViewportBase` (`packages/flutter/lib/src/rendering/viewport.dart`), confirming `paintOffset` on `SliverPhysicalParentData` is the authoritative transform used by `paint`, `hitTestChildren`, `applyPaintTransform`, `describeSemanticsConfiguration`, and `showOnScreen`, and added widget regression tests covering pointer hit-testing, global transformed `SemanticsNode` bounds, `SelectableText` gesture/selection in a shifted short viewport, focus `Scrollable.ensureVisible`, and dynamic short-to-overflow resize transitions.
5. **[Debt 16.E — User Envelope Heuristic Precedence & Deduplication (RESOLVED)]** ([`lib/src/domain/user_message_presentation.dart`](lib/src/domain/user_message_presentation.dart), [`lib/src/protocol/history_protocol.dart`](lib/src/protocol/history_protocol.dart), [`test/protocol/history_protocol_test.dart`](test/protocol/history_protocol_test.dart)):
   - **Problem**: `HistoryProtocolAdapter._userAttachments` and `parseUserMessagePresentation` needed protocol-boundary metadata bounding, strict structured `UserInput` precedence, semantic deduplication against legacy text envelopes, structural header parsing without false positives or preview delimiter spoofing, and safe `&#x20;\` cleanup.
   - **Implemented Fix (`ADAPT_NATIVE`)**: Enforced protocol-boundary normalization and deduplication via `normalizeUserAttachments` (`HistoryItem.attachments`) and `parseUserMessagePresentation` (`seenAttachmentKeys`, `structuredPaths`, `maxUserAttachments = 16`, `maxAttachmentLabelLength = 160`, `maxAttachmentPathLength = 1024`, `maxAttachmentPreviewLength = 2048`, `maxEnvelopeHeaderScanCharacters = 16 * 1024`), tightened `_parseLegacyEnvelope` to require both valid parsed entries and a top-level request delimiter outside quoted previews, restricted `_cleanUserMessageText` to `&#x20;\` continuation artifacts (preserving literal `` `&#x20;` `` in user prose), and added protocol- and presentation-level adversarial tests.
